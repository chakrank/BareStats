# Security Policy

## Supported Versions

Only the latest release receive security patches and updates.

| Version | Supported          |
| ------- | ------------------ |
| 1.0.x   | :white_check_mark: |
| < 1.0   | :x:                |

## Reporting a Vulnerability

The BareStats project takes the security and integrity of user environments seriously, particularly regarding zero-driver safety and anti-cheat compatibility.

If you believe you have discovered a security vulnerability or anti-cheat conflict in BareStats:

1. **Do not disclose the issue publicly.** Please refrain from opening a public GitHub issue for sensitive security vulnerabilities.
2. **Private Disclosure Channels:**
   - **GitHub Security Advisories (Recommended):** Use the [Report a Vulnerability](https://github.com/chakrank/BareStats/security/advisories/new) tab on the GitHub repository.
   - **Direct Email:** Alternatively, send an email to **chakrank@hotmail.com** with the subject line `[SECURITY] BareStats Vulnerability Report`.
3. **Information to Include:**
   - A description of the vulnerability and its potential impact.
   - Exact steps or minimal proof-of-concept to reproduce the behavior.
   - Operating system version (e.g., Windows 10 22H2, Windows 11 24H2) and hardware architecture.
   - Any relevant logs or environment details.

## Response & Disclosure Process

* **Acknowledgement:** We will acknowledge receipt of your vulnerability report within **48 hours**.
* **Assessment & Fix:** We will evaluate the report, keep you informed of remediation progress, and prepare a patch in a private repository branch.
* **Coordinated Disclosure:** Once a fix is verified and released, public credit and release notes will be coordinated with the reporter.
